CONSTRUCTION.  Given strategies S = {baseline (opus×20), length3 (3-tier:
haiku/sonnet/opus), length2 (2-tier: sonnet/opus)} and per-(strategy, task)
measurements from .verdicts/economics-routing-savings/2tier.tsv,

    floor_i  =  min { cost(s, i)  |  s ∈ S  and  correct(s, i) = 1 }
    floor    =  Σ_{i=1..20} floor_i

floor is a strict lower bound on any router operating in S at 20/20
accuracy: any 20/20 router on task i picks some s* with correct(s*, i) = 1,
so its per-task cost is ≥ floor_i; summing preserves the inequality.
The floor is TIGHT — the witness assignment {T_i} achieving floor_i for
all i is constructed explicitly in verify/numerics_economics_pareto_floor.hexa
(FLOOR_TIER_IDX table, lines 153-176).

INTERPRETATION.
  • The canonical 2-tier length router (length2) captures 99.5% of the
    achievable saving on this manifest — only $0.00139 / 20 tasks of room
    remains under the strongest closed-form floor we can construct from
    the strategies actually sampled.
  • The remaining 7 tasks where length3 is cheaper than length2 are all
    "borderline" prompts where the 3-tier router happened to dispatch
    haiku and saved $0.00005-$0.00076 each (mostly stochastic noise:
    same-tier, slightly fewer output tokens on a particular call).
  • The 0.44 pp gap is below per-call sonnet/haiku stochastic variance
    on this manifest (cf. threshold_sweep_summary.txt — τ-sweep showed
    ~1.5 pp noise at the same all-sonnet dispatch).
  • CONCLUSION: length2 is "operationally at the floor" — no heuristic
    router using these strategies can save materially more at 20/20.

HONEST LIMITATIONS.
  (a) MANIFEST-CONDITIONAL.  The floor holds for THIS 20-task workload
      and the 3 strategies actually run.  A cheaper tier/strategy that
      was never sampled (e.g. a hypothetical "haiku2" or a different
      decoding) cannot lower it.  Adding strategies can only tighten
      the bound, not relax it.
  (b) STRATEGY-LEVEL, NOT TIER-LEVEL.  Anthropic's `total_cost_usd`
      field is authoritative; the per-task `model` column in the TSV
      is unreliable under `claude --bare -p` (cache-prefix accounting
      artifact, cf. 2tier_summary.txt CAVEAT D).  We treat each
      (strategy, task) pair as the proof atom rather than (tier, task).
      This is operationally correct — what a router can dispatch IS a
      strategy, not a tier in isolation.
  (c) ACCURACY-MONOTONE FLOOR.  The floor only counts (s, i) entries
      with correct(s, i) = 1.  If a cheaper strategy answered wrong
      (e.g. baseline task 14), its cost is excluded by construction.
