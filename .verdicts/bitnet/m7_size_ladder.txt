# template, NO GQA (kv_heads==heads). Microsoft's BitNet b1.58 2B4T (M1) is

# this is the only loadable ternary SIZE set the b1.58 line ever shipped. Each was
# self-converted bf16/fp16 safetensors -> GGUF f16 (convert_hf_to_gguf.py

# TQ2_0 type-35 kernel). GGUFs kept local (project_bench_sot).

#   (1.3B/3B TQ2_0 bpw > 700M because token_embd + output stay higher precision;
#    only the ternary linear layers go to 2-bit — vocab/embed dominate at small N.)
#
# FINDING: smaller ternary COLLAPSES FURTHER — accuracy is MONOTONIC in size
#   (15% -> 15% -> 20% -> 30% across 700M/1.3B/3B/2B4T). Every size is BELOW the
#   usable floor (15/20). The two smallest (700M, 1.3B) bottom out at 3/20 = 15%,
#   HALF the 2B4T 30%. So 30% is NOT a hard ternary FLOOR independent of scale —
#   it DROPS with size. The 2B4T's higher score is partly capacity and partly
#   instruct-tuning (the base 1bitLLM models cannot follow "reply with X only"
#   and ramble); both effects push the same direction (smaller+base = worse).
#   Note: a 3B BASE model (20%) still beats 1.3B/700M base (15%) — pure capacity
#   scaling is visible even within the base-only set, before the instruct bonus.
