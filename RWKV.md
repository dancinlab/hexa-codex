# RWKV — attention-free RNN LLM evaluation (domain SSOT)

@goal: Empirically validate RWKV's core architectural claims — linear-time inference and constant memory (no KV-cache) — on the self-hosted SANDBOX substrate against a Transformer baseline, and land a closed-form memory/latency-vs-context law.

> Rides on the SANDBOX measurement substrate (sibling domain). Source: https://www.rwkv.com/
> RWKV = 100%-attention-free RNN with Transformer-level quality; claims linear-time inference,
> constant space (no KV-cache), infinite context. Latest: RWKV-7 "Goose" (2.9B / 7.2B), RWKV-8 WIP.
> Linux Foundation AI project. Runnable via llama.cpp / rwkv.cpp GGUF on the substrate.

- [x] M2 Constant-memory — **CLOSED, SUPPORTED (not falsified).** Context-length sweep of the cache buffer (MiB) at context construction: **Qwen KV-cache grows EXACTLY O(n)** — 6→12→24→48→96→192 MiB at ctx 512→1024→2048→4096→8192→16384 (doubles precisely with ctx); **RWKV recurrent state is FLAT at 20.62 MiB across the entire sweep, including ctx 65536** (a 128× span). The state is `1 cell, 32 layers, 1 seqs` — a single fixed-size RNN state (`R(f32) 0.62 + S(f32) 20.00 MiB`), context-independent by construction. Peak-RSS (`/usr/bin/time -l`) corroborates: RWKV 2356 MB@512 → 2353 MB@16384 (flat within noise), Qwen 512 MB → 706 MB (**+194 MB ≈ the 192 MiB KV growth**). Closed-form law (g0, recompute 🟢): **Qwen KV(ctx) = ctx·12 KiB/tok = ctx·0.01171875 MiB/tok, intercept 0, R²=1** (12288 B/tok = 24L·2kvh·64d·2·2B, architecturally exact); **RWKV state(ctx) = 20.62 MiB const** (slope 0). Memory crossover at ctx≈1760 — beyond that RWKV uses *less* total cache memory, gap diverges (4.66× at 8192). Falsifier ("RWKV memory grows beyond a flat band") **NOT triggered** (slope=0). `bench/rwkv_m2m3_ctx_sweep.hexa` · `verify/numerics_rwkv_m2m3_laws.hexa` (8/8 laws 🟢) · `.verdicts/rwkv/m2_constant_memory.txt` + `m2m3_ctx_sweep.tsv`. - [x] M3 Linear-time — **CLOSED, SUPPORTED (not falsified).** Two-axis latency sweep via `llama-bench` (the engine quirk: stock `llama-completion -f <big-file>` drives rwkv7 prefill through a pathologically slow path — a ~1500-tok prompt ran >4.75 min; the dedicated `llama-bench` binary handles rwkv7 cleanly + fast, machine-readable CSV). **PREFILL** (total ms vs ctx, warm): RWKV 4005→59760 ms over ctx 512→8192 (16× ctx → 14.9× time = **LINEAR**, t/s flat ~128-155); Qwen 273→14174 ms (16× ctx → **51.9× time = SUPERLINEAR**, t/s degrades 1880→578). **DECODE** (tok/s vs context depth): RWKV **FLAT ~10 t/s, depth-independent** (ms/tok max/min = 1.24×, does NOT grow); Qwen **degrades linearly** 80.75→22.76 t/s (ms/tok 12.4→43.9 = **3.55× slower @8192**). This reproduces + extends the prior inline partial (Qwen decode 8.95→11.49→31.85 ms/tok) AND lands the missing RWKV half. Closed-form laws (g0, recompute 🟢): RWKV prefill **power-law exponent p=0.962≈1** (R²=0.996, O(n)); Qwen prefill **p=1.366>1** (Δp=0.40, attention O(n^>1)); RWKV decode **slope≈-0.001 ms/tok per ctx-tok** (no trend, O(1)); Qwen decode **slope=+0.00363, R²=0.985** (O(n)).
